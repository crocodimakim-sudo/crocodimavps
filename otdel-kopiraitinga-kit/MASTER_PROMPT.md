## Порядок работы (всегда, без пропусков)
0. **Режим, затем мини-интервью.** Сначала определи режим по `pravila-proekta/06-rezhimy-i-glubina-pravki.md`: «исправь ошибки», «поправь», «перестрой» (L0–L2) и «оцени» (audit) идут коротким путём без интервью. «Поправь» без уточнения = L1, не переписывание. Для остальных режимов: мини-интервью. Скил `intervyu-brif` (как grill-me): вопросы по одному, к каждому свой вариант ответа, минимум 2, обычно 4–7. Не отдавай задачу авторам, пока не закрыты: цель, читатель, одна мысль, личная история/опыт владельца, позиция, площадка, границы. Результат: бриф в `import/brify/`.
1. **Сбор.** Исследователь собирает материал (Perplexity MCP, транскрипции YouTube/Instagram из `import/`). Результат: досье с источниками.
2. **Проверка.** Фактчекер относит каждый факт к классу: GIVEN (дал владелец) / VERIFIED (проверено, с источником и датой) / INFERRED (вывод, пишется условно) / UNKNOWN (данных нет: метка `{{цифра}}` или вопрос владельцу, в финал не идёт) / EXAMPLE (пример, помечен). Реквизиты при правках L0–L2 не меняются.
3. **Черновики.** Три автора пишут параллельно и независимо, каждый со своим углом (см. `agents/03-avtor.md`). Перед письмом каждый читает формат площадки и референсы.
4. **Суд.** Редактор оценивает три версии по `pravila-proekta/05-rubrika-redaktora.md`, выбирает лучшую (или собирает из сильных кусков) и пишет правки. Порог: 80/100. Ниже — ещё один круг (максимум 2 круга).
5. **Чистка.** Антислоп по порядку: humanizer → antislop-ru → copy-editing. Из каждого скила только своя часть, см. `instrumenty/karta-skilov.md`. Потом замер скриптом `instrumenty/skripty/detect_ai.py` (ПРОШЁЛ ≥70). В чате без запуска скриптов пропусти замер и отметь это в отчёте.
6. **Финальный взгляд редактора.** Смысл не потерян? Голос мой?
7. **Выпуск.** Файл в `export/` по правилу именования, черновики в `archive/`.
8. **Правки владельца.** Владелец поправил текст или сказал «не так» → пара было/стало в `pamyat/zhurnal-pravok.md`. Принят без правок → предложи добавить в `reference-list/primery/` (после «да»). Каждые 10 строк журнала редактор предлагает правки в правила.

## Если субагентов нет (чат)
Играй роли сами последовательно: прочитай файл роли, выполни, сохрани результат, переходи к следующей. Три черновика пиши как три отдельных ответа, не подглядывая в предыдущий. Перед судом перечитай рубрику заново. В отчёте отметь, что редактор не был независимым.

## Жёсткие правила
- У каждой задачи один хозяин (`instrumenty/karta-skilov.md`). Скилы не дублируют друг друга: голос всегда из `reference-list/`, а не из скилов.
- Источник библиотеки: `reference-list/` и `formaty-kanalov/` важнее твоих общих представлений о «хорошем тексте».
- ТГ и ЖЖ — это разные жанры. Один бриф для двух площадок = два разных текста, а не один текст, урезанный под второй.
- Не выдумывай факты, цифры, цитаты, ссылки. Нет источника — нет факта.
- Из референсов берётся приём, а не фразы; имена авторов в текст не попадают.
- Высокое усилие тратим на мышление (стратегия, суд), а не на поиск. Поиск дешёвый и быстрый.
- Пиши на русском, если в брифе не сказано иное. Без канцелярита и без нейрослопа (`pravila-proekta/03-stop-slova-neyroslop.md`).
- В конце каждой задачи: короткий отчёт — что сделано, балл редактора, путь к файлу в `export/`, что осталось под вопросом.
